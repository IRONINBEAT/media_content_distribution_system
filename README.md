# Media Content Distribution System

Система для управления медиаконтентом и его распространения на клиентские устройства. Репозиторий содержит FastAPI-бэкенд, веб-интерфейс для операторов и администраторов, а также минимальные файлы для деплоя через `systemd` и `nginx`.

## Что умеет система

- управлять пользователями с ролями `admin`, `operator`, `video_uploader`;
- регистрировать устройства и отслеживать их состояние через heartbeat;
- назначать устройствам плейлисты из видео, изображений и PDF;
- хранить настройки длительности воспроизведения для разных типов файлов;
- синхронизировать токены устройств после обновления пользовательского токена;
- предоставлять веб-кабинет для загрузки файлов, настройки расписания вещания и управления доступом.

## Как устроена работа

1. Пользователь загружает медиафайлы через веб-интерфейс.
2. Файлы связываются с одним или несколькими устройствами.
3. Устройство периодически отправляет heartbeat на `/api/heartbeat`.
4. Устройство запрашивает актуальный плейлист через `/api/check-videos`.
5. Если состав плейлиста изменился, сервер возвращает ссылки на скачивание и параметры воспроизведения.

## Локальный запуск

### 1. Установить зависимости

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### 2. Перейти в каталог backend

```bash
cd backend
```

### 3. Инициализировать базу данных

```bash
python init_db.py
```

Скрипт создаёт SQLite-базу `signage.db`, тестового администратора, одно устройство и несколько файловых записей.

Тестовые учётные данные из сид-скрипта:

- логин: `admin`
- пароль: `pass`

### 4. Запустить приложение

```bash
uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

После запуска будут доступны:

- API: [http://127.0.0.1:8000](http://127.0.0.1:8000)
- Swagger UI: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)
- веб-интерфейс: [http://127.0.0.1:8000/web/login](http://127.0.0.1:8000/web/login)

## Основные сущности

### User

- учётная запись оператора системы;
- хранит роль, токен доступа устройств и таймаут heartbeat.

### Device

- клиентское устройство с уникальным `device_id`;
- имеет статус `unverified`, `active` или `blocked`;
- может иметь расписание вещания: `broadcast_start_time` и `broadcast_end_time`.

### File

- медиаобъект, привязанный к пользователю;
- поддерживаемые типы: `video`, `image`, `pdf`;
- хранит `duration_config` и дополнительную метаинформацию.

## Веб-интерфейс

Маршруты из [`backend/web_routes.py`] покрывают:

- вход и выход пользователя;
- просмотр устройств и файлов в личном кабинете;
- загрузку и удаление файлов;
- управление статусом устройств;
- настройку расписания вещания;
- перевыпуск токена пользователя;
- настройку heartbeat timeout;
- CRUD-операции над пользователями для роли `admin`;
- назначение файлов устройствам и устройств файлам;
- редактирование времени показа контента.

## Основные API-эндпоинты

Маршруты из [`backend/main.py`]:

- `POST /api/heartbeat`  
  регистрация устройства и обновление его активности;

- `POST /api/check-videos`  
  проверка актуальности плейлиста и получение ссылок на скачивание;

- `POST /api/sync-token`  
  синхронизация токена устройства после перевыпуска пользовательского токена;

- `GET /api/admin/users`
- `POST /api/admin/users`
- `DELETE /api/admin/users/{user_id}`
- `GET /api/admin/devices`
- `POST /api/admin/devices`
- `DELETE /api/admin/devices/{device_id}`
- `GET /api/admin/files`
- `POST /api/admin/files`
- `POST /api/admin/files/upload`
- `DELETE /api/admin/files/{file_id}`

## Поддерживаемые форматы файлов

На уровне валидации разрешены:

- `mp4`
- `png`
- `jpg`
- `jpeg`
- `pdf`

Для разных типов файлов система автоматически формирует базовую конфигурацию воспроизведения:

- изображение: фиксированная длительность показа;
- видео: длительность ролика;
- PDF: длительность для каждой страницы.

Примечание: анализ PDF и видео выполняется только если в окружении доступны `PyPDF2` и `moviepy`.

## База данных

Используется SQLite с файлом `signage.db`. Подключение настроено в [`backend/database.py`].

При старте приложения вызывается `ensure_device_schedule_columns()`, которая добавляет в таблицу `devices` поля расписания вещания, если они отсутствуют.

## Ограничения и нюансы текущей реализации

- в репозитории используются относительные импорты и пути, поэтому рабочая директория при запуске имеет значение;
- значение `BASE_URL` в API захардкожено в [`backend/main.py`], для production его лучше вынести в конфигурацию;
- сид-скрипт создаёт демонстрационные записи в БД и подходит для локального старта, но не для production;
- в `requirements.txt` отсутствуют некоторые опциональные библиотеки для анализа медиа, хотя код умеет использовать их при наличии.
